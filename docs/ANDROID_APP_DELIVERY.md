# Android application delivery

The portal's versioned APIs, scoped authentication, correlation IDs, mobile-responsive pages, hosted payment boundary, deep-link-ready notifications, and provider-neutral contracts form the Android backend foundation. A native Android release remains a separately signed client artifact.

Delivery requires an approved application ID, supported OS policy, secure token storage, MFA/session flows, accessibility, offline/error states, universal/app links, FCM, hosted payment handoff, privacy disclosures, analytics consent, crash reporting, device testing, Play integrity/security review, signed builds, Play Console listing, staged rollout, and rollback ownership. No Android app is represented as published until store approval succeeds.
